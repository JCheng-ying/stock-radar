# Stock Radar · 产业链信息处理器

按"五个面"整理美股五大板块（AI / 量子计算 / 机器人 / 航空航天 / 自动驾驶）的信息，生成一个
自包含的静态网页，并在情况发生变化时推送到手机。个人研究用，不构成投资建议，没有任何下单功能。

| 面 | 看什么 | 数据从哪来 |
|---|---|---|
| 产业面 | 需求、供给、资本开支、技术进步、产业政策；公司在产业链的位置 | `data/chains/*.json`（人工整理的知识库）+ Summizer 图谱 |
| 基本面 | 收入、毛利率、EBITDA 利润率、EPS、自由现金流、RPO | Yahoo Finance 季报、SEC XBRL |
| 预期面 | 现价与一致目标价的差距、盈利预测 90 天修正、财报超预期幅度 | Yahoo Finance 一致预期 |
| 资金面 | 美债收益率 / 美元 / 信用利差（以年为周期）、板块 ETF 资金流、个股估值 | Yahoo Finance |
| 情绪面 | VIX、恐贪指数、估值拥挤度、杠杆 ETF 成交占比 → 具体点位 | Yahoo Finance、CNN |

## 网页里有什么

- **总览**：资金面、情绪面、五大板块 × 三浪的位置矩阵、IGV 分化上涨检查、板块资金流、点位信号、财报日历。
- **板块页 = 物品栏**：每个板块列出几个被大面积使用的产品（AI 助手、AI 机柜、AI 芯片、人形机器人、
  火箭、卫星、Robotaxi……共 17 个）。点开一个产品是可旋转的 **3D 爆炸拆解图**：拖动旋转、滚轮缩放、
  滑块控制拆开程度；左侧是按"谁提供什么"分组的零件清单（共 236 个零件）。点任一零件，下面列出
  做这个零件的股票、它在零件里的角色、"⚙ 决定效率"和"▲ 主升浪触发点"。
- **公司详情**（点任何一行）：五个面各一张卡片，每个分数下面列出依据；季度图表、目标价区间、
  SEC 8-K 重大事件、新闻、Summizer 图谱关系。
- **零件里的三层信息**：① 产品对比——同一个零件各家做的具体产品、差异、绑定的客户（人工研究，每条带来源；
  目前完成了第一批 18 个零件，其余按 `REFRESH_INSTRUCTIONS.md` 第 3 节持续补）；② 竞争与合作——人工研究
  的关系 + Summizer 图谱里涉及这些公司的关系；③ 每家公司业务描述里和该零件相关的英文原句，附 Yahoo
  简介和 10-K 原文链接（全部公司自动生成）。
- **财报明细**（公司详情里）：最近 5~6 个季度和 4 个财年的利润表 / 现金流 / 资产负债表主要科目
  （收入、成本、毛利、研发、销售管理、营业利润、EBITDA、净利润、EPS、经营现金流、资本开支、自由现金流、
  股权激励、现金、债务、递延收入、存货、股数、RPO），带环比 / 同比；分析师对本季 / 下季 / 今年 / 明年的
  EPS 和收入预期；历次 EPS 实际 vs 预期；财报后股价反应；8-K 财报新闻稿和 10-Q / 10-K 原文链接。
- **财报页**：即将发布（带一致预期）和最近已发布（带结果和股价反应）。
- **判断标准页**：资金面、情绪面、浪位、个股各项分数、点位信号、推送的全部规则、公式、阈值、数据来源和
  更新频率。总览和板块页的每张卡片也可以展开看“怎么算出来的”，逐项列出当前值、规则、得分和来源。
- **实时报价**：网页打开时和之后每 2 分钟，浏览器直接从腾讯行情取最新价（不经过本机脚本）；
  其余数据以定时刷新为准。
- **全部公司**：可排序、按板块和信号筛选。
- **推送记录**：发过的每一条通知。

## 股票池从哪来

两层：

1. **人工确认**（约 510 只）：`data/chains/*.json` 里每个零件下手写的公司，带一句"它在这个零件里做什么"。
   其中标 ◦ 的是业务多元、这个板块只占一小部分的公司（如量子板块里的微软）——展示但不计入浪位统计。
2. **全市场自动发现**（约 235 只，网页上标"自动"）：`python -m src.discover scan` 从纳斯达克的上市
   公司名单拿到 NYSE + Nasdaq + AMEX 全部约 7000 只证券，筛出市值 2 亿美元以上的非金融公司约 2800 家，
   抓每家的主营业务描述存到 `data/profiles.json`；每次刷新时用每个零件的英文关键词（`kw`）去匹配。
   整词匹配，关键词出现在描述开头权重更高，证据不够强的不收；每个零件最多 10 家。
   **自动发现的结果没有人工核对，会有误配**，也不计入浪位统计。名单 30 天重扫一次即可。

## 浪的位置怎么判断

每个板块的公司按所在环节分成三浪：一浪基础设备 → 二浪 B 端应用 → 三浪 C 端应用。每一浪用六项检查：

价格两项：篮子近 3 个月相对标普 500 的强度、站上 50 日线的公司占比。
财报四项：收入增速中位数、毛利率改善的公司占比（产品力）、EBITDA 利润率改善的公司占比
（经营效率）、RPO 同比增速中位数（长期大单）。

再结合过去一年的涨幅，分成：尚未启动 / 财报已改善价格未反映 / 价格先行财报待验证 / 启动初期 /
主升浪进行中 / 主升浪中的整理 / 回调中 / 过热。另外单独检查 IGV（软件 ETF）是不是"有分化的上涨"。

标了 ◦ 的公司（比如量子板块里的微软）业务多元，这个板块只占它一小部分——照常展示，但不计入浪位统计。

## 点位信号

`情绪热度`（0 极度悲观 ~ 100 极度乐观）由 RSI、52 周区间位置、偏离 200 日线合成。

- **关注买点**：基本面 ≥ 60、预期面 ≥ 58、热度 ≤ 38——好公司处在悲观区，利空大概率已定价。
- **回调风险**：热度 ≥ 80——利好大概率已被消化。
- 其余：观察 / 趋势中 / 中性 / 谨慎 / 弱势。

全部是写死在 `src/analyze.py` 里的规则，阈值可以改。

## 使用

```bash
python3 -m venv .venv && source .venv/bin/activate && pip install -r requirements.txt
./run.sh              # 刷新一次（首次约 2~4 分钟，之后有缓存）
open index.html
```

其它用法：`./run.sh --quick`（只刷新行情和 SEC，财报用缓存，几分钟跑完）、`./run.sh --no-push`（只刷新网页）、`python -m src.main --force`（忽略缓存）、
`python -m src.main --rebuild`（不联网，用上次数据重新生成网页）。

### 手机推送

1. 手机装 [ntfy](https://ntfy.sh) App，订阅一个自己起的、随机一点的 topic（名字相当于密码）。
2. `cp .env.example .env`，把同一个名字填到 `NTFY_TOPIC=`。

不填就只记录到网页的「推送记录」，不发手机。会推送：新财报落地、进入关注买点 / 回调风险、
浪位变化、VIX 或市场情绪进入极端区、IGV 分化上涨信号变化、三天内的财报日、单日涨跌超 8%。
只在"和上一次相比发生了变化"时才发，财报季单次最多 12 条，其余合并成一条。

### 定时任务

```bash
./schedule/install.sh             # 工作日交易时段每 30 分钟 + 盘后 4 次自动跑 run.sh
./schedule/install.sh --uninstall
```

同一个脚本还会装一个监听任务：Summizer 的 `data/graph.json` 一有变化就自动快速重建网页。

```bash
python -m src.main --todo         # 列出还没做人工研究的零件
python -m src.main --news         # 只刷新多来源新闻（约 10 秒），其余用上次数据
python -m src.newscheck           # 列出上次研判以来的新信息（Summizer 新文章 / 重要推送 / 主流新闻），末行 MATERIAL 或 NOTHING
```

Claude 端另有两个定时任务：每天 14:20 的完整研判，以及每小时 :25 的“即时增量研判”
（先跑 `--news` 和 `newscheck`，有重要新信息才补写研判并发布，没有就不动网页）。
「博主观点」页的数据在 `data/blogger.json`：同一个每小时任务发现 Summizer 里视野环球财经的新笔记
（`~/Desktop/Summizer/data/youtube/rhino/notes/日期.md`）后，按股票拆成 评价 / 信息支持 / 后续走势 / 估值 / 操作计划 / 其他看法 写进去。

### 网址

公开网址：https://jcheng-ying.github.io/stock-radar/（有网址的人都能看）。每次刷新后 `publish.sh` 把最新网页覆盖发布到 `gh-pages` 分支；主分支只放代码、知识库和研判记录。

### 发布到 GitHub Pages（已配置）

新建一个 GitHub 仓库，`git remote add origin <地址>`，在仓库 Settings → Pages 里选从 main 分支
根目录发布。之后 `run.sh` 每次刷新完会自动提交并推送。把网址填到 `.env` 的 `SITE_URL=`，
推送通知点开就直接跳到网页。注意仓库如果是公开的，网页任何人都能看到。

## 目录

```
data/chains/*.json   产品拆解知识库（板块 → 产品 → 零件 → 公司；含 3D 形状和匹配关键词）
data/profiles.json   全市场公司业务描述（discover scan 生成，不进 git）
src/discover.py      全市场扫描 + 关键词匹配
data/notes.json      Claude 定期写入的重大消息判断（见 REFRESH_INSTRUCTIONS.md）
data/snapshot.json   最近一次的完整数据
data/alert_log.jsonl 推送历史（只追加）
src/fetch.py         联网取数      src/analyze.py   五个面打分、浪位、点位
src/alerts.py        变化检测 + ntfy   src/build_site.py  生成 index.html
web/template.html    网页模板（原生 JS + SVG；3D 用内嵌的 three.js，不依赖 CDN）
```

## 已知局限

- Yahoo Finance 的季报只有最近 5 个季度，所以同比只能算最新一个季度；一致预期和财报数据偶尔有
  口径不一致（比如 GAAP 与非 GAAP 混用导致"超预期 80%"这类异常值），打分时已做截断。
- RPO 只有按美国会计准则披露的公司才有（台积电、ASML 等外国公司没有）。
- FINRA 融资余额网站挡爬虫，杠杆风险用"三倍做多 ETF 成交额占比"代替；融资余额可手动写进 `notes.json`。
- 3D 模型是用方块、圆柱等基本几何体拼的示意图，不是真实的工业模型；看不见的部分（软件、服务、客户）
  用底部一圈六边形表示。
- Yahoo 对密集请求限流：公司池扩到 700 多家后，首次刷新会有一部分公司拿不到财报（显示为"—"），
  多跑几次 `./run.sh` 会逐步补齐（已拿到的有缓存）。
- 拆解知识库是人工整理的，零件划分和公司归属都可能有疏漏，需要按 `REFRESH_INSTRUCTIONS.md` 定期维护。
- SEC 接口要求请求头带联系邮箱，默认值是占位符，建议在 `.env` 里设置 `SEC_UA`。
